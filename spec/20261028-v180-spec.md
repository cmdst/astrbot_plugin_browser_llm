### 3.1 B1 · 投递层：保留同权目标，极简重写

- **裁决**：交付 **L1（通道同权）+ L2 子集（生态同权）**，落 `core/proactive.py`，硬上限 **300 行**；**不交付 L3**。
- **理由**：同权的可感知收益全在 L1+L2——消息从 `Context.send_message`（正规主动发送口）出去、并在其它插件眼里有一次 `on_decorating_result` / `on_after_message_sent`。L3 需要复制核心 stage（内容安全、分段、TTS、前缀、t2i），那是**双份实现**且核心一升级就漂移。
- **代价（必须写进交付摘要）**：① 主动消息**不过内容安全 stage**；② 群聊消息历史库（`message_history_manager`，非 `conv.history`）在开关打开时会记一条 `role="bot"`；③ 平台找不到时**不静默**（WARN + 记账），也不重发。
- **用户可改口**：
  - 改口 1「不重写，继续用 `event.send`」⇒ 删除 A5/§6，`browse_task_status` 仍可做（读任务簿），但**放弃**分段/TTS/记忆类插件可见性；`core/proactive.py` 不新增。
  - 改口 2「要 L3（内容安全也过）」⇒ **超本版范围**：需核心提供官方 API，属 fix 侧事项，不写进 v1.8.0。

### 3.2 B2 · 后台引擎：轻量 7 态任务簿

- **裁决**：`core/tasks.py`（≤450 行）= **任务簿 + 队列 + 预算 + 7 态 + 终态渲染**；**删除** `core/background.py`；不搬 IMAGO 的 10 态 / stage / 动态闸 / 配额 / 配文。
- **理由**：两个只读工具的价值取决于"状态说得清"。旧引擎只有 `running` + 4 终态，"结果已生成、正在投递、投递挂了"三件事挤在终态里，于是生产出现 **77 分钟无终态**（V-1）时既不能答"卡在哪"，也不能答"发出去了没"。
- **代价**：`tests/test_v175_background.py`（47 条）与 `test_v175_background_wiring.py`（6 条）必须**重写**（不是删掉了事，见 §10.4 的守卫映射表）；行为变化两处：**（a）全局并发满载改为排队**（队列上限 8，超出仍【拒绝】）；**（b）预算从提交时刻起算，排队时间计入**。
- **用户可改口**（明确写出）：
  - 改口「别动那 1006 行」⇒ 保留旧引擎，两个工具改读 `BackgroundRegistry`，**状态仍是 5 态**（无 `queued` / `delivering`），于是：`browse_task_status` 只能答"在跑/完成/失败/超时/取消"，**答不了"发出去了没"**；本版 A5 仍做、A6 取消；门禁条数区间相应下调（§10.2 备注）。

## §4 A1 P0：两层修法与 R-A1 严格性判据

### 4.1 根因（生产实测 2026-10-28，用户口述日志）

- 现象：子代理八次调 `browse_act`，**八次**都返回 `【拒绝】R-A1 动作必须是 JSON 对象，收到 str`；连 `back` / `wait` 这类零参数动作也被拒。
- 根因在**边缘**，不在闸门：模型把 `action` 参数（工具 schema 里是对象）写成了一个 **JSON 字符串**（部分还套 ` ```json ` 围栏），`_make_browser_tool._handler(event, **kwargs)` 原样把 `kwargs["action"]` 透传给 `browse_act`，`parse_action` 收到 `str` 只能按 R-A1 拒绝。
- **不许这样修**：把 `parse_action` 的 `isinstance(payload, Mapping)` 放宽成"字符串也试着解析"。那会让 `R-A1..R-A14` 的码表语义悄悄改变（"不是对象"这一整类失败从此消失），且 8/8 全拒的真因（模型侧传错类型）被永久掩盖。

### 4.2 第一层：边缘容错 `coerce_payload`（**逐字契约**）

放在 `core/action_model.py`（纯 Python 模块，已有 `json` import），紧邻 `parse_action`，并加入 `__all__`。

```python
def coerce_payload(payload: Any) -> Any:
    """边缘容错（**不是闸门**）：把模型偶发写成 JSON 字符串的载荷解开一层。

    契约（四条，逐条有测试，见 EX-01..EX-09）：
    1. ``Mapping`` ⇒ **原对象返回**（`is` 同一性成立，零拷贝）；
    2. ``bytes`` / ``bytearray`` ⇒ 按 UTF-8 解码（errors="replace"），再按字符串处理；
    3. ``str`` ⇒ 去空白 → 去掉**一层** ``` 围栏（首行 ``` 或 ```json、末行 ```）
       → 空串则返回原值 → `json.loads` ⇒ 结果是 ``Mapping`` 才返回它，否则返回原值；
    4. 其它类型（None / int / list / dict 之外的一切）与**任何异常** ⇒ 原值返回。

    只解一层：**不做递归、不做第二次 json.loads**（双重编码仍交给闸门按 R-A1 拒）。
    绝不抛异常；绝不改写入参。
    """
```

**实现约束（评审逐条对）**：

| # | 约束 | 理由 |
| --- | --- | --- |
| C-1 | 只解**一层**：`json.loads` 最多调用 1 次 | 两次即等于"猜模型意图"，会让 R-A1 的证据消失 |
| C-2 | 解析结果必须是 `collections.abc.Mapping` 才采用 | list/数字/字符串一律原样返回 ⇒ 交给闸门 |
| C-3 | 围栏剥离只去**首尾各一行**，不碰内容里的 ``` | 防误伤代码块正文 |
| C-4 | 空串 / 纯空白 ⇒ 原值返回（不要 `json.loads("")` 抛错路径） | 让闸门给出准确 R-A1 |
| C-5 | 全部 `except Exception`（宽），且**不记日志**（日志在调用点记一次） | 容错层不制造噪声 |
| C-6 | 不 `strip()` 入参本身（不可变字符串无所谓，但 Mapping 分支必须零处理） | 保证 C-1 的"绝大多数情况零成本" |

### 4.3 第二层：闸门 `parse_action` 保持严格

| 项 | 规定 |
| --- | --- |
| `isinstance(payload, Mapping)` 判断 | **一字不改**（在 R-A14 预算检查之后、R-A13 之前的位置不变） |
| R-A1 的码与语义 | 不变：非 Mapping ⇒ `R-A1 动作必须是 JSON 对象，收到 <type>` |
| **唯一允许的改动** | R-A1 的 `hint` 末尾追加一句提醒：`"请直接传对象，不要传 JSON 字符串、不要加引号或代码围栏"`（纯文案，不影响任何码） |
| 拒绝码表 | 仍**恰好** `R-A1..R-A14`（`tests/test_v175_action_model.py:127` 的断言不许改） |
| `ACTION_JSON_SCHEMA` / 冻结 schema 文件 | 不动 |

### 4.4 两个接线点（**只解一层**的边界在这里）

| # | 位置 | 改动 | 说明 |
| --- | --- | --- | --- |
| W-1 | `main.BrowserLLMPlugin.browse_act(self, event, action: dict = None)` | 方法体第一行：`action = am.coerce_payload(action)` | 模型来的第一跳；`_act_impl` **不再** coerce |
| W-2 | `main.BrowserLLMPlugin.browse_screenshot(self, event, target=None, full: bool = False)` | `if target is not None: target = am.coerce_payload(target)` | 同一根因的第二个入口（`main.py:3049` 的 `parse_action` 探针消费它） |

**纪律**：

1. **只在这两个方法边界**调用（工具边界 = 模型参数进入插件的第一跳）；不许在 `_act_impl` / `_screenshot_impl` / `core/executor` 里再调一次（否则"只解一层"无法证明，且双重解码会把 `<str>` 变成 `<dict>` 掩盖真实问题）。
2. coerce 后**必须走原闸门**：`parse_action` 仍是唯一判定点，不许绕开。
3. 真非对象**仍拒**：`coerce_payload(42)` / `coerce_payload(None)` / `coerce_payload("[1,2]")` 都原样返回 ⇒ R-A1。

### 4.5 R-A1 严格性判据（三条，任一条被放宽即评审 reject）

| # | 判据 | 断言（执行级） |
| --- | --- | --- |

### 4.6 变异验证（**必须红**，见 §11.6 MV-01/MV-02）

## §5 `core/tasks.py`：轻量 7 态任务簿（≤450 行）

### 5.1 状态机：7 态与转移表

```
                 ┌──────────── cancel_all / shutdown ────────────┐
                 │                                               ▼
  submit ──► queued ──[拿到并发槽]──► running ──► delivering ──► cancelled
                │                       │            │
                │                       │            ├──► succeeded
                ├──[排队期预算耗尽]──────┼────────────┼──► failed
                │                       └──[预算到点]┼──► timeout
                └──[cancel_all]──────────────────────┘
```

| 态 | 含义 | 可达性 | 终态 |
| --- | --- | --- | --- |
| `queued` | 已受理，等全局并发槽（**未开始执行**） | 全局在跑数 ≥ `max_parallel` 时 | 否 |
| `running` | 执行体在跑，预算在走 | 拿到槽后 | 否 |
| `delivering` | 工作阶段已结束（工作结果已定），正在做**唯一一次**投递 | 必然经过 | 否 |
| `succeeded` | 工作成功（终态正文已发出或投递失败都已记账） | | **是** |
| `failed` | 执行体抛异常 | | **是** |
| `timeout` | 预算到点被中断（含**排队期**超预算） | | **是** |
| `cancelled` | 插件重载 / `cancel_all` / 用户取消 | | **是** |

**转移合法性（非法转移必须**抛 `ValueError`** 而不是静默改字段）**：

| from → to | 允许 | 备注 |
| --- | --- | --- |
| `queued → running` | ✅ | 同时写 `started_at` |
| `queued → timeout` | ✅ | `reason="queued_budget"`，**不占用**执行槽 |
| `queued → cancelled` | ✅ | `cancel_all` 在排队任务上 |
| `running → delivering` | ✅ | 同时写 `finished_at`（工作结束时刻） |
| `running → cancelled` | ✅ | 取消也是"工作结束" ⇒ 直接到 `delivering`（投递一条"已取消"终态），**不**跳过投递 |
| `delivering → succeeded/failed/timeout/cancelled` | ✅ | 由 `note_delivery` 写终态 |
| 其余任意转移 | ❌ | `ValueError(f"非法状态转移 {src}→{dst}")` |
| 终态 → 任意 | ❌ | 终态不可变（除了 `note_delivery` 重复调用返回 `False`） |

> **注意**：`running` **不直接到终态**——必须先到 `delivering`。这是"每条任务恰好一次投递"的结构性保证（EX-18）。

**行为规定（逐条）**：

| # | 规定 |
| --- | --- |
| T-1 | `submit` 是**同步**函数，内部 `asyncio.create_task` 起执行体与看门狗各一个（命名 `browser_llm:{task_id}` / `…:watchdog`） |
| T-2 | 四道闸的**顺序固定**：同会话单飞 → 去重（窗口内同 `task_key`）→ 全局排队 → 队列上限 |
| T-3 | 排队：`len(running) < max_parallel` ⇒ 立即开跑（`accepted`）；否则入队（`queued`），队列长度 ≥ `max_queue` ⇒ `busy` 拒绝 |
| T-4 | 预算**从 `created_at` 起算**（`deadline = created_at + budget_s`）：排队耗尽预算 ⇒ `timeout(reason="queued_budget")`，**不启动执行体** |
| T-5 | 执行体：`asyncio.wait_for(runner(progress), timeout=remaining_s())`；`CancelledError` **不吞**（登记终态后原样上抛） |
| T-6 | 看门狗：睡到 `deadline` 硬取消；再过 `grace` 仍未收尾 ⇒ 强制 `delivering → timeout`（`reason="watchdog"`），**只补一条** |
| T-7 | 收尾幂等：`_finalized` 标志保证执行体与看门狗只允许一方进入 `delivering` |
| T-8 | `deliver` 只调**一次**；`deliver` 抛异常 ⇒ `DeliveryNote(attempted=True, succeeded=False, error="DeliveryRaised:<Exc>")`，终态照常写 |
| T-9 | `recent_of` 只返回 `state == succeeded` **且** `result_text` 非空的记录（`failed/timeout/cancelled` 的回看归状态工具，见 §7.5） |
| T-10 | 保留上限：终态记录超 `max_done` 时淘汰最老的（淘汰后 `recent_of` 查不到 ⇒ RR-2/无结果） |
| T-11 | `set_result` 写正文时同时算 `result_chars` / `result_digest` / `truncate_result(max_chars)` 的截断标记；**正文不进日志** |
| T-12 | 时间源可注入：单测用假时钟把"到点"压成零真实耗时 |

```

### 6.4 单一通道 + 双钩子 + 三形态

| 形态 | 装饰方行为 | 本层动作 | `shape` | `succeeded` |
| --- | --- | --- | --- | --- |
| **A** | 只改链（含分段插件"末段留链"） | 用改写后的链走 `context.send_message` | `"A"` | 发送成功 |
| **B** | 装饰方**自己发了**（置了 `_side_send_started` / `stop_event()`） | **不再发**，认成功 | `"B"` | `True`（无 `_side_send_error` 时）/ `False`（有则记 `SideSend:<code>`） |
| **C** | 清空链且没发（`stop_event()` 或链空） | **不发**，记 `DecoratorSuppressed` | `"C"` | `False` |

**形态判定规则（唯一实现 `classify_after_decorators` 内联在 `deliver` 里，不单独导出）**：

1. `event.is_stopped()` 且 `chain` 非空 ⇒ **照发**（归 A；对应 v1.7.6 的 C′ 裁定：核心对非空链同样照发）；
2. `event.is_stopped()` 且 `chain` 空 且 `_side_send_started` ⇒ **B**（装饰方发了）；
3. `event.is_stopped()` 且 `chain` 空 且 未发 ⇒ **C**；
4. 未 stop 且 `chain` 空 且 `_side_send_started` ⇒ **B**；
5. 未 stop 且 `chain` 空 且 未发 ⇒ **C**；
6. 其余 ⇒ **A**。

> `_side_send_started` / `_side_send_error` 由合成事件的 `send()` 覆写置位（见 §6.5）。**不探别人插件的私有属性**（只读我们自己合成事件上的标记）。

### 6.5 一次逻辑投递的定义（写进模块 docstring）

> **一次逻辑投递** = 对一条任务终态，`context.send_message` 的**恰好一次**调用（或装饰方代发一次）。
> 装饰方把一条消息切成多条、加 TTS、加前缀、改文案，都**不算**第二次投递。
> 本层**不重试、不补发**：`succeeded=False` 也是一次"已尝试"的结果，记账后即终态。

合成事件的 `send()` 覆写（**不**调 `super().send()`——基类只埋点，未来若基类真发送会双发）：

```python
async def send(self, message):                       # 合成事件上的覆写
    self.begin_send_stage()                          # 计数：发送阶段已开始
    self._side_send_started = True
    sent = await self._context.send_message(self._outbound_umo, message)
    if not sent:
        self._side_send_error = ERROR_PLATFORM
        raise RuntimeError(ERROR_PLATFORM)           # 让装饰方知道"没发出去"
```

### 6.6 超时与失败记账

| 情形 | `attempted` | `succeeded` | `error` | 备注 |
| --- | --- | --- | --- | --- |
| 正常（A 发送成功） | True | True | `""` | `channel="context.send_message"` |
| 装饰方代发（B） | True | True | `""` | `shape="B"` |
| 装饰方代发但 `_side_send_error` | True | False | `SideSend:<code>` | |
| 装饰方抑制（C） | True | False | `DecoratorSuppressed` | 不是"没尝试"，是"没人发" |
| `context.send_message` 返回 False / 抛错 | True | False | `PlatformNotFound` / `BadSession` | **不重试** |
| 拿不到 astrbot 符号 | True | False | `FrameworkUnavailable` | 降级（测试环境/核心改名） |
| 正文与媒体都空 | **False** | False | `EmptyChain` | 不构造事件、不调通道 |
| 整次投递超 `DELIVERY_TIMEOUT_S` | True | False | `DeliveryTimeout` | 用 `asyncio.wait_for` 包 |
| 单体钩子超时 | 照常继续 | — | 记 `hook_errors += "HookTimeout:<plugin>.<handler>"` | 不中断 |

### 6.7 生命周期纪律（写成代码约束）

1. **后台不持 `event`**：`TaskRecord` 与 `DeliveryTarget` 都不含 event；`deliver` 的 `target` 是快照。
2. **快照在提交时抽**，之后事件对象可以被框架回收（重载/超时都不影响投递）。
3. **合成事件不进任何全局表**（不留引用、不注册 handler）。
4. `plugins_name` 从快照抄（`context.send_message` 之外的白名单语义与前台一致）。
5. 结果类型 `ResultContentType.LLM_RESULT`（让 `split_scope=llm_only` 的分段插件认得）。

### 6.8 不做清单（写死）

| 不做 | 理由 |
| --- | --- |
| 平台回退腿（`platform_fallback` / `event.send` 兜底） | `Context.send_message` 内部已经做了 `platform.send_by_session` 查表；再兜一层等于复制核心逻辑 ⇒ 失败就记账（`PlatformNotFound`），由状态工具暴露 |
| 补偿式第二条 / 重试 | 用户放弃"不丢"优先于"不重"；一条任务只发一次 |
| 六形态细分（v1.7.6 的 A/B/B′/C/C′/D） | 三形态已覆盖可观测差异；细分只增加状态数与测试面 |
| 跨插件识别（`probe_splitter_patch` 之类） | 探别人插件的私有开关 = 耦合；形态判定只看我们自己事件上的标记 |
| 内容安全 / TTS / 前缀 / t2i | L3，不交付（§6.1） |

情形 3 · 投递中（`state=delivering`）：

情形 5 · 本会话无任务：

```

情形 6 · 本会话无任务且无历史：

```
【无任务】当前没有在跑的后台任务（本会话最近 {window_min} 分钟也没有已完成任务）。
```

**状态词表（逐字，`state → 词`）**：`queued→排队中` / `running→在跑` / `delivering→投递中` / `succeeded→完成` / `failed→失败` / `timeout→超时` / `cancelled→取消`。

**行为规定**

| # | 规定 |
| --- | --- |
| TS-a | `task_id` 非空 ⇒ `book.get(task_id)`；记录存在但 `record.umo != 当前 umo` ⇒ 视作**不存在**（跨会话不泄露） |
| TS-b | `task_id` 空 ⇒ 优先 `book.active_of(umo)`（非终态）；否则最近一条终态（窗口内）；都没有 ⇒ 情形 5/6 |
